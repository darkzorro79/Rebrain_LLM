# Блок 03: сервер инференса vLLM

## Практическое задание

### Ресурсы

Вам предоставлена виртуальная машина с GPU-ускорителем (NVIDIA H200) и операционной системой Ubuntu 24.04.

- **Доступы:** SSH, права root (через `sudo`).
- **Предустановленное ПО:** Python 3.12, pip, драйверы NVIDIA (CUDA 12.x).

### Задача

Развернуть высокопроизводительный сервер инференса с использованием библиотеки **vLLM**, который будет предоставлять **OpenAI-совместимый API** для генерации текста.

В качестве модели используйте **Qwen/Qwen2.5-0.5B-Instruct**. Это легковесная Instruct-модель, которая не требует API-токенов Hugging Face (в отличие от Llama 3), что позволит вам сосредоточиться на настройке самого сервера vLLM, а не на управлении доступами.

### Требования к реализации

1. Установить библиотеку **vllm**.
2. Запустить сервер vLLM, который:
   - использует модель **Qwen/Qwen2.5-0.5B-Instruct**;
   - слушает входящие соединения на всех интерфейсах (**0.0.0.0**) на порту **8000**;
   - работает в **фоновом режиме** (например, через `nohup`, `screen`, `tmux` или `systemd`), чтобы процесс не завершился при выходе из SSH;
   - корректно обрабатывает запросы в формате **Chat Completions API** (формат OpenAI).

### Критерии успешного выполнения

- **[Сетевая активность]:** порт 8000 открыт и слушает входящие соединения (TCP LISTEN).
- **[API /v1/models]:** GET-запрос к `http://localhost:8000/v1/models` возвращает JSON со списком, содержащим `Qwen/Qwen2.5-0.5B-Instruct`.
- **[API /v1/chat/completions]:** POST-запрос к `http://localhost:8000/v1/chat/completions` с тестовым промптом (например, `{"model": "Qwen/Qwen2.5-0.5B-Instruct", "messages": [{"role": "user", "content": "Hello"}]}`) возвращает корректный JSON-ответ с кодом **200 OK** и сгенерированным текстом.

## Описание решения в этой папке

Основной сценарий для задания — скрипт **`bash03.sh`**. Он:

- устанавливает vLLM через `pip install vllm`;
- запускает OpenAI-совместимый сервер командой `python -m vllm.entrypoints.openai.api_server` с моделью `Qwen/Qwen2.5-0.5B-Instruct`, хостом `0.0.0.0` и портом `8000`;
- выводит логи в **`vllm_server.log`** и оставляет процесс в фоне через **`nohup ... &`**.

Дополнительно заданы параметры производительности и удобства: `--gpu-memory-utilization`, `--max-model-len`, chunked prefill, лимиты батча, prefix caching и отключение периодической статистики в логах.

**Авторизация API:** сервер поднимается с **`--api-key "my-secret-token"`**. Запросы к защищённым эндпоинтам нужно сопровождать заголовком `Authorization: Bearer my-secret-token` (так сделано в скриптах проверки ниже).

### Проверка критериев

| Критерий | Файл |
|----------|------|
| порт 8000 в состоянии LISTEN | `net_active.sh` (`ss -tuln` и фильтр по `:8000`) |
| GET `/v1/models` и наличие модели Qwen в ответе | `check_models.sh` |
| POST `/v1/chat/completions`, код 200 и поле `content` в ответе | `check_chat_completions.sh` |

Запуск (после старта сервера): `./net_active.sh`, `./check_models.sh`, `./check_chat_completions.sh` (права на исполнение: `chmod +x *.sh` при необходимости).

### Прочие материалы в папке

- **`bash01.sh`**, **`bash02.sh`** — примеры запуска API-сервера для **Meta-Llama-3-8B-Instruct** (учебные варианты, не для финального задания с Qwen).
- **`offline_inference.py`**, **`offline_inference2.py`** — офлайн-инференс через класс `LLM` без HTTP-сервера, также на базе Llama 3.
- **`client_test.py`** — пример клиента на **OpenAI SDK** к локальному `http://localhost:8000/v1`; в коде указана модель Llama 3 — для проверки Qwen нужно заменить `model` на `Qwen/Qwen2.5-0.5B-Instruct` и использовать тот же API-ключ, что при запуске сервера.
- **`opencode.json`** — конфигурация редактора/инструмента с провайдером Ollama (`localhost:11434`), к vLLM на порту 8000 не привязана.
