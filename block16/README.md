# Блок 16: n8n — интеллектуальный дежурный

## Практическое задание

### Задача

Ваша задача — спроектировать отказоустойчивый воркфлоу в n8n, который выступает в роли Интеллектуального дежурного. Система должна получать технические алерты, анализировать их с помощью LLM и выдавать инженеру структурированный отчет в Telegram с возможными причинами сбоя.

### Требования к реализации

**Входная точка (Trigger):**  
Реализуйте прием данных через Telegram Trigger. Воркфлоу должен принимать сообщения с алертами. Алерты можно пересылать из других каналов или просто копировать из письма и передавать боту.

**Архитектура обработки (The Filter & Worker):**

- **Узел фильтрации (Guard):** Используйте ноду AI Agent с моделью gemini-2.5-flash. Ее задача — классифицировать входящий текст. Если это не технический алерт (спам или случайное сообщение), воркфлоу должен завершаться.
- **Узел анализа (Worker):** Если запрос валиден, данные передаются на модель gemini-2.5-flash. Она должна получить не только текст алерта, но и System Prompt.

**Логика ветвления (Flow Logic):**  
Реализуйте обработку ошибок (Error Trigger): если API нейросети недоступно, воркфлоу должен отправить в Telegram «сырой» текст алерта с пометкой "Ошибка анализа: AI недоступен".

**Форматирование и вывод:**  
Итоговый ответ в Telegram должен быть оформлен с использованием Markdown.  
Обязательные блоки в сообщении: Тип проблемы, Уровень критичности, Рекомендация по исправлению (сгенерированная AI).

### Критерии успешного выполнения

- **Технологический стек:** Воркфлоу реализован строго в n8n.
- **Формат сдачи:** В репозиторий (или через форму ответа) необходимо загрузить JSON-экспорт вашего воркфлоу.
- **Проверка сценарием:** При получении алерта `High load average on web-server-01`, система должна прислать в Telegram краткий план диагностики (например: 1. Check top/htop. 2. Verify access logs. 3. Check for zombie processes).

## Описание решения в этой папке

### Основной воркфлоу задания: `Intelligent_OnCall_Alert_Analyzer.json`

Экспорт воркфлоу **«Интеллектуальный дежурный — Alert Analyzer»** закрывает требования практики.

| Элемент | Реализация |
|--------|------------|
| **Вход** | `Telegram Trigger` — входящие сообщения с текстом алерта. |
| **Guard** | `AI Agent - Guard` + чат-модель `google/gemini-2.5-flash` (в проекте подключена через OpenRouter-совместимый credential к узлу типа OpenAI Chat Model). System prompt задаёт роль фильтра и примеры алертов / не-алертов; ответ ожидается в виде JSON `is_alert` / `reason`. |
| **Парсинг Guard** | Узел `Code` (`Parse Guard Response`) выделяет JSON из ответа агента; при сбое трактует сообщение как не-алерт. |
| **Ветвление** | `If` (`Is Technical Alert?`): при `is_alert === true` — в Worker, иначе — `No Operation` (`Stop - Not Alert`), ветка тихо завершается. |
| **Worker** | `AI Agent - Worker` с той же моделью `gemini-2.5-flash`; в промпт подставляется исходный текст из `Telegram Trigger`, system prompt задаёт роль on-call инженера, обязательные блоки (*Тип проблемы*, *Уровень критичности*, *Рекомендация по исправлению*, *Возможные причины*) и правила Telegram Markdown. У Worker включён режим **Continue on Error** (`onError: continueErrorOutput`). |
| **Успешный ответ** | `Send Report` — ответ в чат с `parse_mode: Markdown`. |
| **Ошибка Worker / LLM** | Вторая выходная ветка Worker → `Send Error Alert`: текст с префиксом **«Ошибка анализа: AI недоступен»** и сырым текстом алерта из триггера. |
| **Error Trigger** | Отдельная цепочка `Error Trigger` → `Send Workflow Error` — уведомление в Telegram при падении выполнения (сообщение об ошибке и последнем узле). |

Для проверки из задания достаточно отправить боту строку вроде `High load average on web-server-01`: Guard пропустит её как технический алерт, Worker сформирует структурированный отчёт с нумерованными шагами диагностики (в system prompt явно заложены команды вроде `top` / `htop`, логи, процессы).

**Что настроить после импорта в n8n:** подставить свои credentials для Telegram и для API LLM (в файле указаны ID из учебного инстанса — их нужно заменить на свои).

### Дополнительные материалы в папке

- **`Rebrain n8n_ Guardrails_0.json`** — отдельный воркфлоу про **guardrails**: классификация входа на предмет prompt injection / jailbreak с выводом в строгом JSON (схема `GuardrailSecurityResult`). Полезен как справочная реализация фильтра безопасности, не является обязательной частью сдачи «интеллектуального дежурного».
- **`Rebrain n8n_Интеграция AI-агента и DockerHub MCP-prod.json`** — пример интеграции AI-агента с **DockerHub MCP** (поиск образов и т.п.). Относится к смежной теме курса по n8n и агентам, а не к сценарию приёма алертов из Telegram.

Для сдачи по формулировке задания обычно достаточно приложить **`Intelligent_OnCall_Alert_Analyzer.json`**.
