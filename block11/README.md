# Блок 11: продвинутые RAG-пайплайны (качество поиска)

Материалы курса [«Продвинутые RAG-пайплайны: повышаем качество»](https://my.rebrainme.com/course/llm/task/3152): переранжирование (Cross-Encoder), RAG-Fusion (вариации запроса + RRF), HyDE (гипотетический документ для поиска).

## Практическое задание

### Ресурсы

Вам предоставлен доступ к Git-репозиторию и API-ключ для работы с LLM через прокси-сервер (LiteLLM).

### Задача

Ваша задача — реализовать этап **Re-ranking (переранжирование)** в RAG-системе. Ваша цель — отфильтровать результаты первичного поиска и выбрать наиболее полезный контекст для ответа на технический вопрос.

В корне вашего репозитория создайте скрипт `reranker.py`, который выполняет следующие действия.

#### Подготовка данных

В качестве входных данных используйте фиксированный запрос и список кандидатов (имитация выдачи векторной базы данных).

**Запрос (Query):** «Почему не удаётся подключиться к базе данных?»

**Список документов (Documents):**

- **Док 1:** «Отдел маркетинга вчера обсуждал стратегию провальных подключений к базам данных». (Много ключевых слов, но нулевая польза).
- **Док 2:** «Для исправления ошибок подключения проверьте параметр max_connections в postgresql.conf и перезапустите службу». (Релевантное техническое решение).
- **Док 3:** «Строки подключения к базе данных должны храниться в секретах». (Общая рекомендация, не решающая проблему).

#### Логика переранжирования

1. Инициализируйте модель **Cross-Encoder**, используя библиотеку `sentence_transformers` и модель `cross-encoder/ms-marco-MiniLM-L-6-v2`.
2. Вычислите оценки релевантности (scores) для пар «Запрос — Документ».
3. Отсортируйте документы по убыванию полученного балла и выведите их в stdout.

### Критерии успешного выполнения

- **Git-репозиторий:** в репозитории присутствует скрипт `reranker.py`.
- Скрипт реально использует класс **CrossEncoder** для сопоставления смысловой близости.
