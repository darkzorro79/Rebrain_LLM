# RAG Система Техподдержки

Система поиска и ответов на основе базы знаний техподдержки с использованием векторного поиска и LLM.

## Компоненты

- **base/db/init-pgvector.sql** - SQL скрипт инициализации базы данных с таблицей knowledge_base
- **indexer.py** - Скрипт индексации базы знаний с генерацией эмбеддингов
- **rag_chat.py** - Скрипт поиска и ответа на вопросы пользователей
- **requirements.txt** - Зависимости Python
- **setup.sh** - Скрипт автоматического развертывания системы

Для автоматического развертывания системы:

## Ручная настройка

### 1. База данных

Убедитесь, что PostgreSQL с расширением pgvector запущен:
```bash
cd base
docker-compose up -d
```

### 2. Переменные окружения

Установите переменные окружения (API_KEY обязательна):


```bash

```

## Использование

### 1. Индексация базы знаний

```bash
python indexer.py
```

Этот скрипт:
- Подключается к БД PostgreSQL
- Проверяет существование таблицы knowledge_base
- Индексирует 5 записей базы знаний техподдержки (только если таблица пуста)
- Генерирует эмбеддинги через OpenRouter прокси API
- Сохраняет записи с эмбеддингами в базу данных

**Важно**: При повторном запуске скрипт автоматически пропускает индексацию, если данные уже существуют. Это предотвращает потерю данных при перезапуске контейнеров.

### 2. Поиск и ответы

```bash
python rag_chat.py "Как восстановить пароль?"
python rag_chat.py "Проблемы с принтером"
python rag_chat.py "Часы работы офиса"
```

Этот скрипт:
- Принимает вопрос как аргумент командной строки
- Генерирует эмбеддинг вопроса
- Ищет наиболее релевантный документ в БД (векторный поиск)
- Отправляет найденный контекст и вопрос в LLM
- Выводит ответ в stdout

## База знаний

Система содержит следующие документы техподдержки:

1. Восстановление доступа к корпоративной учётной записи
2. Подключение к удалённому рабочему столу
3. Гостевой Wi-Fi
4. Проблемы с принтером
5. Часы работы и заявки на отпуск

## Требования

- Python 3.8+
- PostgreSQL с расширением pgvector
- Доступ к OpenRouter прокси API (требуется переменная окружения API_KEY)
- Интернет-соединение для работы с API

## Архитектура

```
Вопрос пользователя → Эмбеддинг → Векторный поиск → Контекст + Вопрос → LLM → Ответ
```

Система использует косинусное расстояние для поиска наиболее релевантного контекста в векторном пространстве размерности 3072. API запросы направляются через OpenRouter прокси (https://llm.rebrainme.study) для получения эмбеддингов и генерации ответов.
