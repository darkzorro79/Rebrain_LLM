## Практическое задание

### Ресурсы

Вам предоставлена виртуальная машина с Ubuntu 24.04 с правами root и установленным python. А также — выделенный Git-репозиторий, куда будет необходимо загрузить ответ на задание.

### Задача

Реализуйте помощника системного администратора (`helper.py`), который переводит текстовые запросы в консольные команды.

### Требования к реализации

1. **Интерфейс:** бесконечный цикл ввода (через `input()`), выход по команде `exit`.
2. **Tool Calling:** описание функции `run_shell_command` должно передаваться в модель `gemini-2.5-flash`.
3. **Безопасность:** скрипт обязательно должен выводить команду в терминал и запрашивать подтверждение у пользователя (`y`/`n`) перед вызовом `subprocess.run` или аналогичного модуля.
4. **Обратная связь:** результат выполнения команды (stdout) должен передаваться обратно в модель, чтобы она могла прокомментировать успех или ошибку.

### Критерии успешного выполнения

В Git-репозитории присутствует файл `helper.py` с реализованной логикой.

## Решение в этой папке

Ниже — как устроены файлы блока и как они соотносятся с заданием.

### `practic/helper.py` — эталон под требования курса

- Клиент OpenAI-совместимого API: `base_url` `https://llm.rebrainme.study/`, ключ из переменной окружения `API_KEY`.
- Модель: `gemini-2.5-flash`, в запрос передаётся массив `tools` с функцией **`run_shell_command`** (описание и параметр `command`).
- Цикл **`process_request`**: пока модель возвращает `tool_calls`, для каждого вызова выполняется Python-функция, результат кладётся в историю с ролью `tool` и тем же `tool_call_id` — так stdout/stderr (в виде строки, возвращаемой из обработчика) снова попадает в контекст модели.
- **`run_shell_command`**: печатает команду, спрашивает подтверждение (`y`/`n`, также принимаются варианты yes/no и да/нет), только после согласия вызывает `subprocess.run(..., shell=True, capture_output=True, text=True, timeout=30)`; при отказе возвращает текст об отмене; при ошибке — код возврата и stderr.
- **`main()`**: бесконечный `input("Ваш запрос: ")`, выход по `exit` / `quit` / `выход` / `q`, обработка `KeyboardInterrupt`.

Копия той же логики для примера сдачи в отдельный репозиторий: `practic/user-repo-ldyfd/helper.py`.

### `practic/helper_ollama.py` — локальная отладка через Ollama

Та же идея (интерактивный цикл, `run_shell_command` с подтверждением, передача результата в историю), но `base_url` указывает на `http://localhost:11434/v1`, модель задаётся как `gpt-oss:20b`. Дополнительно: лимит итераций, фильтрация «похоже ли на shell-команду», запасной путь, если модель вставила команду в текст в обратных кавычках — это помогает с моделями, которые хуже соблюдают формат tool calls.

### `main.py` и `main_ollama.py` — одноразовый сценарий с циклом tool calling

Один фиксированный пользовательский запрос (про поиск в `/var/log`), цикл «модель → вызов инструмента → снова модель» до текстового ответа без `tool_calls`. Инструмент назван **`execute_shell_command`** и **без** интерактивного подтверждения — это учебный пример цикла агента, а не полная реализация формулировки практики про `helper.py` и `y`/`n`.

### Запуск эталонного помощника

```bash
python3 practic/helper.py
```

Для варианта с Ollama — поднять сервер Ollama с нужной моделью и запустить `python3 practic/helper_ollama.py`.
